# iCUE Memory Guard v0.2.0

**Experimental prerelease · Windows 11 x64 · JZB Apps**

A local patch for identified string and WMI ownership leaks in Corsair's CPU identification service and CPUID SDK. This version adds an exact-content definition for service 5.54.46.0 and retains the tested 5.52.93.0 definition. Both use the identified SDK 1.3.4.7 image. Setup verifies the original and derived hashes and retains protected originals for recovery; vendor images are not distributed.

Download [iCUEMemoryGuard-Setup-0.2.0.exe](https://github.com/jb14813/iCUE-Memory-Guard/releases/download/v0.2.0/iCUEMemoryGuard-Setup-0.2.0.exe) from [GitHub Releases](https://github.com/jb14813/iCUE-Memory-Guard/releases/tag/v0.2.0). Run Setup as administrator. Windows' built-in PowerShell 5.1 is used; no separate framework, dependency download, driver, resident process or tray icon is added.

Compatibility depends on both file contents, not their version labels. See the [exact hashes and validation limits](https://github.com/jb14813/iCUE-Memory-Guard/blob/v0.2.0/VALIDATION.md). Unknown or concurrently updated files are preserved. An iCUE update can overwrite the fix; rerun Setup only when the resulting pair is supported. There is no automatic patching of unfamiliar builds.

Applying or restoring the fix briefly reloads the CPU-ID service. Restore returns owned patched files to the verified originals for that build. Windows Installed apps also removes the guard application. Unsafe mixed images stop restoration or uninstall and retain recovery material.

The installer uses the retained JZB Apps **self-signed** key. It does not establish public Windows publisher trust or remove SmartScreen warnings. Verify [SHA256SUMS](https://github.com/jb14813/iCUE-Memory-Guard/releases/download/v0.2.0/SHA256SUMS), its detached signature, the public certificate and the installer using the [published instructions](https://github.com/jb14813/iCUE-Memory-Guard/blob/v0.2.0/SIGNING.md).

**Experimental:** modifying vendor files invalidates their vendor signatures. Instability, sensor-function loss, application-control blocks or update conflicts are possible. Finite validation does not establish compatibility with every system, game or future update. See the validation record for actual test coverage.

Patch checks and recovery data stay local; there is no automatic diagnostic upload.
